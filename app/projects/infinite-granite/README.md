# InfiniteGranite

A browser-only kitchen design studio at `/projects/infinite-granite/`, linked from the portfolio's space project deck. No AI calls, uploads, backend, or third-party requests are required while designing. The existing Next.js static export deploys through GitHub Pages.

## Layout and placement

Six presets retain the chosen finishes. A blank custom plan starts with a 4×4 through 10×10 grid of 36-inch squares. Choose a component and facing, then paint cells on separate floor and wall-cupboard layers. Tall appliances and wall cupboards cannot occupy intersecting volumes. Build the scene, then select, resize, rotate, move, duplicate or remove any module. Maximum: 200 components. Room dimensions support 12–60 ft so connected runs can grow beyond 30 ft. Starting a new grid is reversible with Undo after building; cancelling keeps the current kitchen.

`connectedEdit.ts` applies connected transforms atomically: width/depth growth anchors the negative world edge, carries touching followers, pushes encountered pieces, and expands/recentres the rectangular room if needed. Shrinking closes connected seams without automatically shrinking the room. View-relative arrow buttons swap adjacent modules along the nearest floor axis, retaining unequal module sizes and the run’s outer endpoints. At the end of a run they leave the design unchanged; Position controls remain available for free movement. Windows retain 1/3/6/12-inch shift steps. A separate Component type selector replaces the selected module with the new kind and usable dimensions while retaining its ID and refitting the run. Disable “Adjust connected pieces & room” for constrained edits. Sink width changes the bowl, cabinet, and counter cutout together. `room.ts` supplies four independently enabled walls, editable heights, wall-bound windows/doors with real openings, frame overlap checks, and backsplash rectangles clipped to actual counter spans and openings. Wall boundary edits move attached pieces and reject collisions.

`placement.ts` resolves geometry edits against room limits and other components. Edges within three inches snap together. Movement stops at the first obstacle, including proposals crossing an entire neighbor; intentional moves away from shared edges remain possible. Resizing/rotation preserve contacting edges where possible and are rejected if no clear placement exists. New pieces use the nearest free space; room shrinking is atomic. Dimensions use half-inch increments and centres use quarter-inch increments to preserve seams through save/reload. Vertical clearance includes range hoods and faucets. Legacy saved designs with pre-existing overlaps remain available with visible overlap warnings, so users can rearrange them without losing their work.

## Materials and rendering

`materials.ts` provides a supplier-independent catalogue, company grouping, numeric-aware code order, and case/space/punctuation-insensitive code/name search. Eight procedural Studio collection options retain their original IDs. `tceStone.ts` contains all 97 unique products on the five official TCE Stone Canada listing pages audited September 7, 2026. TCE labels them quartz; 21 are marked clearance/discontinued and retain that label. The catalogue heading says 94 colours, but its actual product listings total 97.

TCE photographs are served locally as 97 optimized WebP textures (at most 1536 px / 320 KB each) plus 97 lazy-loaded thumbnails. Full-slab imagery uses published slab dimensions; 20 products have only a detail photo, whose estimated pattern scale is disclosed in the picker. Attribution, source URLs, original image URLs, dimensions and checksums are in `public/assets/infinite-granite/tce/catalogue.json` and `ATTRIBUTION.md`. `node scripts/generate-tce-catalogue.mjs` regenerates typed picker data from the audited manifest. Add another supplier as a separate typed material array, then include it in `MATERIALS`; the picker will group/search it automatically.

Three.js loads only for this route and renders on change. Supplier textures load on demand, with at most three concurrent requests and a bounded texture cache (up to eight entries, or enough for every active material). Loading/failure messages disclose flat-color placeholders. Actual images use an untinted material and world-coordinate mapping. Counters have beveled edges and real sink holes; modeled footprints stay inside module dimensions. Lighting uses environment reflections, daylight shadows, and physical surface finishes. GPU resources are disposed on teardown, eviction, and initialization failure.

Stone previews default to Enhanced pattern visibility, with Natural and Bold options in both finish panels. Luminance contrast strengthens veins and grain while retaining hue, and softer stone reflections reduce washout. Supplier image files remain unchanged; wood bypasses the contrast adjustment. The setting persists with designs and supports undo/redo and legacy saves.

Touch orbit/pinch, keyboard-accessible camera controls, and component dropdowns work on phone and desktop. Fullscreen uses the browser API where available and an edge-to-edge viewport fallback elsewhere, including iPhone. It supports either orientation, resizes the camera, traps focus, restores background scrolling, and offers Exit/Escape. Clicking a component, wall, window, or door selects it for a compact editor directly in the viewer, with size, rotation, shifts, duplication, removal, and collapsed finish/position details. Add is always available in the stage toolbar and the fullscreen editor; Remove selected component sits directly beneath the type selector. View opens visibility controls in the reserved editing panel, outside the camera toolbar. Show/hide controls cover walls, upper cupboards, appliances, backsplash, openings, and individual elements; Show all restores visibility without changing the design. Fullscreen includes a collapsible finish panel with the same countertop library, cupboard colours/profiles, and sink/faucet controls as the regular editor. Edit, Room, and View tabs make scene editing and visibility available in fullscreen too. It sits beside the scene on desktop/landscape and below it on portrait phones/tablets, reserving visible space for the kitchen. Changes share persistence and undo/redo with the regular editor; collapsing the panel retains its material search. The viewer follows the visible viewport when the phone keyboard opens. This remains an approximate preview; verify dimensions and physical samples before renovation.

## Persistence and verification

The current design and up to four comparison options persist in `infinitegranite.studio.v1` localStorage. Input validation supports previous saved designs, custom grids, and supplier materials. Storage failure leaves the editor usable. Download saves the current view as a PNG.

Run `npm run typecheck`, `npm run lint`, `npm test`, and `npm run build`. Tests cover preset bounds, placement sweeps/snapping, trapped resizing, keyboard movement, vertical conflicts, room shrinking, a 200-piece grid, repeated save/reload round-trips, all 97 product assets/checksums, catalogue search/order, and actual beveled geometry/sink cutouts at supported size extremes. Browser QA covers custom painting/layers, rejection of overlaps, resizing, persistence, supplier texture selection, and phone portrait/landscape plus desktop fullscreen. Finish-control QA also verifies changing all three categories while expanded, retaining search through changes/collapse, shared undo/redo, returning to the regular editor, reload persistence, and keyboard focus/escape handling.
